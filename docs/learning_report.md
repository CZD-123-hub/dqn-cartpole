### 3. 强化学习基础

围绕 DQN-CartPole 项目，我也开始学习强化学习的基本概念。强化学习和监督学习最大的不同在于，它没有一开始就给定完整的标注数据，而是让智能体不断与环境交互，在试错过程中收集经验并改进策略。

在 CartPole 环境中，智能体需要根据当前状态选择向左或向右推小车。环境会返回新的状态和奖励。如果杆子保持平衡，智能体通常每一步获得 1 分；如果杆子倒下或小车越界，一轮 episode 就会结束。

目前我重点理解了以下概念：

- `state`：环境状态，例如小车位置、小车速度、杆子角度和杆子角速度。
- `action`：智能体采取的动作，在 CartPole 中只有向左和向右两个动作。
- `reward`：环境给出的即时奖励。
- `done`：当前 episode 是否结束。
- `Q value`：在某个状态下采取某个动作后，未来可能获得的累计回报。

这些概念虽然看起来简单，但真正写代码时会贯穿整个训练流程。例如 Replay Buffer 保存的就是 `(state, action, reward, next_state, done)` 这样的经验。

## 五、必读论文阅读情况

实验室资料中列出了一些必读论文。考虑到我目前还在打基础阶段，我先选择了两篇对深度学习发展影响很大的论文进行阅读：

详细读书笔记已经整理在 `docs/paper_notes.md` 中。下面是我对两篇论文的阶段性理解。

### 1. Attention Is All You Need

这篇论文提出了 Transformer 架构。论文最重要的思想是：处理序列数据时，不一定必须使用 RNN 或 CNN，也可以完全依靠注意力机制完成建模。

Transformer 的核心模块是 Self-Attention。我的理解是，Self-Attention 让序列中的每个 token 都可以根据当前上下文去关注其他 token，而不是只按照固定顺序逐步传递信息。这样做的好处是可以更好地建模长距离依赖，同时也更容易并行训练。

论文中还提出了 Multi-Head Attention 和 Positional Encoding。Multi-Head Attention 可以让模型从多个角度学习 token 之间的关系，Positional Encoding 则用于补充序列位置信息，因为 Transformer 本身不像 RNN 那样天然包含顺序结构。

阅读这篇论文后，我最大的收获是认识到模型结构设计会深刻影响任务效果。Transformer 不只是一个更强的模型，更是一种新的序列建模思路。后来的 BERT、GPT 等模型都建立在这一基础上。

### 2. BERT

BERT 是基于 Transformer Encoder 的预训练语言模型。它的核心思想是先在大量无标注文本上进行预训练，再针对具体下游任务进行微调。

BERT 的一个重要训练任务是 Masked Language Model。它会随机遮盖输入句子中的一部分 token，然后让模型根据上下文预测这些被遮盖的词。这样模型就能同时利用左侧和右侧上下文，学习更强的双向语言表示。

我对 BERT 的理解是，它把 NLP 模型训练分成了两个阶段：第一阶段学习通用语言知识，第二阶段适配具体任务。这种“预训练 + 微调”的思想非常重要，因为很多实际任务中的标注数据有限，而无标注文本相对容易获得。

虽然我当前的 DQN-CartPole 项目不是 NLP 项目，但阅读 BERT 对我理解深度学习很有帮助。它让我意识到，深度学习项目往往可以拆成若干关键模块，例如模型结构、训练目标、数据来源和评估方式。DQN 项目也可以按类似思路拆解：先理解环境交互，再实现 Replay Buffer，再实现 QNetwork，最后完成训练和测试。

## 六、DQN-CartPole 项目进度总结

### 1. 项目目标

DQN-CartPole 项目的目标是使用 DQN 算法解决 `CartPole-v1` 环境。训练完成后，希望智能体可以根据当前状态选择合适动作，使杆子持续保持平衡。任务书中的目标是训练后的智能体能够稳定运行，例如持续平衡 200 步以上，并可视化训练过程中的 reward 曲线。

需要特别说明的是，DQN-CartPole 不需要像图像分类或文本分类那样提前下载固定数据集。它的训练数据来自智能体和环境的交互过程。每次交互产生一条经验：

```text
(state, action, reward, next_state, done)
```

这些经验会保存到 Replay Buffer 中，再随机采样用于训练 Q 网络。

### 4. 随机策略实验

随机策略是项目的第一步，主要用于确认 Gymnasium 环境可以正常运行。脚本逻辑比较简单：每一轮先 reset 环境，然后随机选择动作，调用 `env.step(action)` 与环境交互，累计 reward，直到 episode 结束。

随机策略本身没有学习能力，因此通常只能坚持较少步数。这个结果是合理的，也说明仅靠随机动作无法稳定完成任务，后续需要通过 DQN 让智能体学习更好的动作选择策略。

### 5. Replay Buffer 实现

Replay Buffer 是 DQN 中非常重要的模块。它的作用是保存历史经验，并在训练时随机采样一批经验。

如果神经网络只按照时间顺序学习最新经验，样本之间相关性会很强，训练容易不稳定。Replay Buffer 通过随机采样打乱样本顺序，可以让训练过程更接近普通的 batch 训练。

当前实现中，我使用 `deque(maxlen=capacity)` 管理固定容量缓存。当经验数量超过容量时，最早进入缓存的经验会自动移除。采样时返回 NumPy 数组，后续可以方便地转成 PyTorch tensor 进行训练。

## 七、当前问题与认识

目前我对项目有几个阶段性认识。

第一，强化学习和监督学习的思路差别比较大。监督学习通常有固定数据集和标签，而强化学习的数据来自智能体与环境的交互。DQN-CartPole 项目的“数据集”其实就是不断收集到的经验。

第二，DQN 的训练稳定性是后续需要重点关注的问题。Replay Buffer、Target Network、epsilon-greedy、学习率和 batch size 都会影响训练效果。如果训练不稳定，reward 曲线可能会波动很大。

第三，当前 CPU 环境可以满足 CartPole 项目需求。现阶段更重要的是先把算法流程写清楚，而不是过早纠结 GPU 或复杂网络结构。
